# 2026-07-08

Conducted a security review of an internal client/server system that renders third-party content. The design leaned on a loopback/same-origin trust assumption — "it's only ever talking to itself, so it can trust what it receives" — but that assumption didn't actually hold once permissive CORS and a missing Content-Security-Policy were factored in, since third-party content rendered in the same context could reach further than the design assumed. Designed and began implementing a multi-part fix: tightening the origin/CORS story, adding a real CSP, and separately patching a race condition that review surfaced along the way, plus expanding automated test coverage around all of it. A generic version of the CSP tightening looks like this:

```
# before: no CSP at all, third-party content inherits the page's full privileges
# after: a default-deny policy with explicit, narrow allowances
Content-Security-Policy: default-src 'none'; frame-src https://trusted-widget.example; script-src 'self'
```

Separately, diagnosed an expired access token that was blocking package installs and a container image build, then set up a local Kubernetes-based simulator environment and confirmed a test pod successfully booted the full internal application stack (virtual display/VNC, backend service, and client service), with remote-content provisioning left as a follow-up.
