A local console's seed script was dying immediately at boot with an unhelpful environment error. Traced it to a startup guard shared by both the seed command and the normal serve command: a required config value had no default in any mode, so anything that boots the app fails the same way before touching anything else. The actual gap wasn't the check itself — that part was correct and already documented in the project's environment-variable reference — it was that the quick-start instructions told readers to run the seed command first, before ever pointing them at that reference table. Fixed the docs so the prerequisite is stated right where the blocking command is, not just in a separate table three sections away.

Also: a nearby local dev script assumed a `docker compose` plugin that wasn't installed on this machine (only the base `docker` CLI and a `buildx` plugin were present), which failed every compose-based path (serve, worker, manual scaling) the same way. Documented the actual dependency instead of just the symptom.

Spent most of the day on a multi-step CSV bulk-import wizard: column mapping, live diffing of what would change, and validation. The interesting design problem was the validation pipeline — it had grown into one large function mixing format checks, uniqueness checks, and registry lookups, which made a specific perf trap easy to miss: an early version resolved uniqueness by loading the *entire* existing dataset client-side up front, which works fine on a small fixture but doesn't scale to a real fleet. Broke the monolithic validator into an ordered sequence of small async steps (parse → structural checks → dedup → scoped-lookup), so the expensive step is isolated, testable on its own, and swappable later without touching the others:

```ts
type ImportRow = Record<string, string>;
type StepResult = { ok: true; row: ImportRow } | { ok: false; row: ImportRow; error: string };

type ValidationStep = (row: ImportRow, ctx: Context) => Promise<StepResult>;

async function runPipeline(rows: ImportRow[], steps: ValidationStep[], ctx: Context) {
  const results: StepResult[] = [];
  for (const row of rows) {
    let current: StepResult = { ok: true, row };
    for (const step of steps) {
      if (!current.ok) break;
      current = await step(current.row, ctx);
    }
    results.push(current);
  }
  return results;
}
```
