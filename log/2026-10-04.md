# 2026-10-04

Working on a notification-management feature for an internal admin tool, I found that confirmation and unsubscribe links sent to recipients were being built from the wrong base URL, pointing to an internal logging endpoint instead of the correct application route; I traced the link-building logic and fixed it to derive the URL from the correct mount path. I also added a feature letting administrators resend a confirmation message to a pending notification-group member, reusing existing membership logic that already supported resetting a member to pending status with a fresh token rather than writing new business logic from scratch. On the frontend, I made the list of notification channel types dynamic based on what's actually enabled in the environment instead of hardcoding options, added a button to trigger the resend action for pending members, and clarified wording so a webhook-based destination reads clearly as a channel rather than a person. I also restored a navigation entry that had been accidentally dropped during an earlier revert. All backend and frontend test suites, type checks, and lint passed, and I did a clean rebuild to verify the new UI before handing off for end-to-end testing.
