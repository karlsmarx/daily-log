# 2026-09-29

A launch-history view gave each launch no visible identifier and was going to get slow as history grew, since every load re-read live state for every launch. Each launch now shows a short id with a copy button, when it ran, who started it and what it targeted. The list pages newest-first, backed by an index so deep pages cost the same as the first. Final step results are saved when a launch finishes, so only running launches trigger a live check. A load test on 2,000 synthetic launches caught a bug I would have missed: every poll re-fetched all loaded pages, so request volume grew with each "show older" click. Polling only the running launches made it constant. Measured about 20 ms per page at any depth, an index-only scan with no sort, and passing backend and frontend suites.

The pagination change comes down to replacing offset paging with a keyset condition on the sort columns. The first query below scans and discards every skipped row. The second seeks straight to its starting point through a composite index.

```sql
SELECT * FROM events
ORDER BY created_at DESC, id DESC
OFFSET 1000 LIMIT 10;

SELECT * FROM events
WHERE (created_at, id) < ($1, $2)
ORDER BY created_at DESC, id DESC
LIMIT 10;
```

---

Testing the console against production-sized data showed several interactions freezing the browser tab for 15 to 19 seconds, and a handful of pages that were slow at the median. The causes were mostly the same: pickers rendering tens of thousands of options, validation running in one long block, whole collections paged into the browser to find one record, and counts computed by scanning everything. I capped pickers and made them say when they hide matches, time-sliced the import validation, loaded single records instead of paging in the fleet, and replaced the scans with grouped queries. I added a seeded large dataset and an automated browser suite that measures each page, picker and import step against fixed time budgets. Results were compared against the base build on the same data, with unchanged pages as controls plus a second run of the same build to show run-to-run noise. Before publishing, I checked every number in the write-up against the raw measurements and corrected several. After the change nothing freezes, and every measured page and interaction is within budget at the median except one large file upload.
