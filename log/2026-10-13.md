# 2026-10-13

A personal hardware project to design a modern, minimal 3D-printable replacement case for a vintage game console, keeping every original button and port working. Published sources didn't give port or board coordinates, so I wrote a parametric CAD script that exports print-ready STL files and flags every dimension still needing a physical measurement. The first model came out about 272 mm wide, too big for common printer beds, so the script now exports each shell whole and in halves. Checking the owner's hand measurements against the manufacturer's scaled board drawing agreed to within about 4 mm. It also showed my first layout was mirrored left to right, so I rebuilt it smaller and added a clear light-guide strip around the lid for LEDs. Automated checks confirm no parts overlap, the lid swings open about 100° without hitting anything, and every split part fits a 220 mm bed.

A deploy job failed right after a routine version bump, and the question was whether the application changes caused it. They didn't. The infrastructure code had been refactored so two cloud log groups moved to a new resource address, and the stored state still used the old one. Terraform therefore planned to destroy and recreate same-named resources, and the creates started before the destroys finished and failed with an "already exists" error. The fix is to re-run the job, then declare the address change explicitly with moved blocks so other environments get a rename instead of a destroy and recreate that would lose retained logs. I reported this without changing anything, since the repo was outside the scope of the task.

I was asked to review a change that adds remote terminal access to lab devices through multi-hop connections. To keep my own branch clean, I ran it in a separate worktree against an isolated database seeded from a colleague's snapshot of real lab entities. I ran the existing suites and a mutation-testing pass over the new code. Most surviving mutants were test gaps rather than bugs. In two cases an earlier guard fired first and hid the guard I meant to test, so the tests passed for the wrong reason. Others were untested defaults, input trimming, connection timeouts, a cap on captured output, interrupt handling and a socket-error path. I judged one survivor equivalent, since the removed guard only made repeated calls on already-finished work. The list of tests to add was drafted, with a live smoke test against a real device planned once the mutation run finished.

A multi-workstream performance pass on a large web admin console, with one commit per workstream. The work moved paging, search and counting to the server, shared identical in-flight requests, cached short-lived dashboard reads, moved import parsing into a Web Worker, and deferred rendering of heavy pickers until reached. After the main work, I ran several simplification reviews to shrink the diff and applied most of their findings. One finding broke a test that relied on the guard it removed, so I reverted it, and I left alone changes that would only have grown the diff. 145 frontend and 84 backend tests passed afterwards. I also found that a few API changes would break callers outside the console. Rather than choose silently, I held that decision for the owner, presenting back-compat against documenting the breaks. The session ended with a written handoff and a resumable prompt so the next session could pick up where this one stopped.

A QA pass turned up three related backend problems, plus a UI history issue found along the way. In the first, data stayed reachable after its parent record was deleted, because the history query never checked that the parent still existed. In the second, two different items sharing a version label produced a server error instead of a clear business error. In the third, a list column and its filter disagreed about which flows an item contained. I fixed each so deletion now returns not-found and the ambiguity gives an explicit conflict, and made the column and filter use the same source. I also made the default selection identify items by unique ID instead of label, and grouped version history accordingly. Before and after were checked with live API calls against a throwaway database, and each new frontend guard was shown to fail its test when removed. After rebasing, 2006 frontend tests and 5246 backend tests passed, with one unrelated test flaking once under parallel load and passing on re-run.

I wanted to learn how to build explainer-style animations like the ones in a long technical video, with persistent diagrams, objects that fly between layouts, and a consistent visual unit. After analyzing its structure, I chose a code-driven animation framework and built a small playground reproducing one scene, where squares fly one at a time into card outlines while a counter ticks up. Setup hit a module-format incompatibility between the framework's plugin and the project config, fixed by adjusting the project settings. Headless-browser screenshots confirmed the scene renders and the animation plays, and revealed two small bugs: the counter hit its final value early and used the wrong plural at one. Both are fixed.

A colleague's proposal for near-instant device health data made a few claims about how existing reporting and probing work, and I checked each against the code. It blurred two separate mechanisms, and a couple of other claims couldn't be settled from the repo alone. The harder problem was transport, since deployed devices have limited outbound connectivity. I compared two options: a direct HTTPS collector, which needs a network change at every site, and reusing an existing vendor message broker that devices already talk to. The broker route needs no network change and gets device identity for free, but ties us to a vendor for setup and capacity. I outlined the broker design, with batching, acknowledged delivery and local buffering so offline devices lose nothing, and listed the questions for the broker's operators. This was research only, and the next step is a small QA trial.
