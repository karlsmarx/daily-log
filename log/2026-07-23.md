# 2026-07-23

Continued the least-privilege work from yesterday on a second component: a device CLI tool that, like the service manager, had been reaching for broad root access to do routine device operations. Replaced that with a dedicated system group plus a small set of tightly scoped sudo rules, so the CLI can perform its handful of privileged operations without a general-purpose escape hatch:

```sudoers
Cmnd_Alias DEVICE_CTL = /usr/local/bin/device-ctl reboot *, /usr/local/bin/device-ctl reset *
%device-ops ALL=(root) NOPASSWD: DEVICE_CTL
```

Membership in `device-ops` is the only thing that grants those two operations — nothing else `sudo`-able comes along for free. Verified the change by rebuilding the container image from scratch and re-running it through the orchestration test suite, rather than trusting a live-edited container that might not reflect what a fresh build produces.

Also fixed shell installer scripts that were silently swallowing errors or falsely reporting success on failed setup steps — a `set -e` gap where a piped command's exit code was getting lost.
