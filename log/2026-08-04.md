# 2026-08-04

Renamed an internal package and updated all consuming code, configuration, and documentation to match. While in there, found a data-consistency bug in a fact-collection component: two related methods each resolved duplicate keys their own way, so the same input could end up with a different "winning" value depending on which method touched it. Unified them onto one resolution rule and added a regression test to cover it:

```ts
// before: two call sites, two different tie-break rules
const byLast = Object.fromEntries(entries); // last write wins
const byFirst = entries.reduceRight((acc, [k, v]) => ({ ...acc, [k]: v }), {}); // first write wins

// after: one shared, explicit rule used everywhere
function resolveDuplicates(entries: [string, unknown][]) {
  return Object.fromEntries(entries); // documented: last write wins
}
```
