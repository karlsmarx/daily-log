# 2026-08-18

Ran real-environment testing of a database concurrency/locking design in a containerized test cluster, exercising the paths the design doc claimed were safe under concurrent access. One of them wasn't: an existing data-sync command turned out to unconditionally wipe tables before rewriting them, regardless of whatever locking safeguard was supposed to be gating writes elsewhere. The locking design was correct for the paths it covered — this command just didn't go through it at all, so the safeguard being "correct" gave false confidence about a codepath it never touched. Updated the design documentation and risk evaluation to reflect that more precise root cause instead of the vaguer "there might be a concurrency issue" framing it started with.

Also:
- Diagnosed and cleaned up a locally-run Kubernetes test cluster that had been left unpruned for weeks and was OOM-killed, recreating it with resource limits and writing an automated cleanup/bootstrap script plus a standing instruction to run it before future test sessions.
- Resolved a complex git merge/rebase conflict caused by a directory rename colliding with parallel feature work on the main branch, verified the resulting code built and tests passed, and prepared a clean single-commit history pending a force-push to update the code review.
- Documented the rationale for adding a lightweight database adapter as an alternative to a heavier ORM-based one, then root-caused and fixed a flaky CI test suite caused by a known upstream bug in a native SQLite binding sharing state across parallel test workers, resolving it via a test-runner worker-recycling config change.
