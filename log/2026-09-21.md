# 2026-09-21

Reviewing an experimental plan for a machine-learning research project, I caught that one section was implicitly holding a small, single-GPU academic project to the bar of matching published speedups from large industrial inference stacks — an unfair and not particularly meaningful comparison for the resources available. The fix was to reframe the key comparison as a same-hardware, same-model before/after measurement (compiled vs. uncompiled, on identical rented hardware), keeping the industrial numbers only as qualitative context rather than a target. This also validated an existing progression in the plan of starting with small models and scaling up only as reproducibility allows, which was worth stating explicitly as a deliberate scoping decision rather than an implicit one. Separately, evaluated a few small mixture-of-experts model architectures for a specific "always-active" expert path needed by the next experiment phase, checking which ones had that path built in versus which would need a fallback design if the always-active feature wasn't present.

The task was to bring two display-brand drivers up to parity with two others in a fleet display-control system, so that a device power-on feature (used to wake displays automatically during a scripted handover process) worked over a serial connection as well as network, for panels that are physically unreachable any other way when fully powered off. Since both device protocols already used a transport-agnostic interface and the wire format was identical between serial and network, the fix was mostly a configuration/registry gap rather than new driver logic — added the missing serial parameters, updated stale documentation and tests that had asserted serial was unsupported for those two brands, and verified the full test suite passed. Separately, investigated adopting a legacy display-control protocol for portability across a wider set of brands, but found no surviving specification or protocol capture anywhere, so declared it out of scope. Also diagnosed a failed device-access script: it was silently depending on a local network tunnel that hadn't been started, not a bug in the script itself, and resolved a follow-on credential/SSH access issue so the device could be reached directly going forward. Real-hardware validation of the driver changes is still pending lab access.
