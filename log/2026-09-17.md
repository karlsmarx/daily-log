# 2026-09-17

While manually testing a new template-management feature, a validation bug surfaced: submitting a blank-after-trim title (or similarly invalid fields) returned a server error instead of a clean validation error. The root cause was that an internal validation exception was being thrown correctly by the service layer, but the corresponding controller was missing the mapping to turn that exception into a proper client error response, unlike sibling controllers in the same codebase. The fix added that missing mapping so all affected validation paths returned the correct error type with a useful message instead of failing with a generic server error. Before/after checks confirmed the previously broken cases now returned correct responses while valid submissions still succeeded, and a regression test was added at the controller level to close the gap, since existing tests only covered the service layer. Separately, further exploratory testing turned up a second issue: it was possible to save a reference to a nonexistent version/flow pair without any server-side check.
