# 2026-07-13

A flaky end-to-end test suite turned out to have two independent causes. One was environmental: a stale Kubernetes test pod left over from a prior run caused false failures on the next one, so broadened the test's failure-skip logic to correctly treat connection timeouts as retryable instead of only one specific error response it had been special-cased for. The other was configuration drift: an environment-variable override loaded inconsistently depending on which command-line entry point was used to invoke the suite, fixed by making the test runner config resolve it the same way regardless of entry point.
